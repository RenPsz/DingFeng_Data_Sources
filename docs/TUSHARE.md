# Tushare 接入方案（规划中）

> **状态：未实现。** 当前 `cnfin.py` v1.1.0 **不包含** `TushareSource`，也不会读取 `TUSHARE_TOKEN`。
> 本文是后续升级的设计与验收基线，不代表现有能力。落地前不要在生产代码中按本文接口调用。

- 文档更新时间：2026-10-24
- 适用目标：A 股日频行情、复权、财务、分红、交易日历、宏观
- 数据定位：**付费主源**，不是唯一源，也不是盘中实时源

---

## 一、结论与定位

Tushare 适合替代当前免费链路中的“日频 + 基本面”部分，因为这些数据对字段稳定性、历史连续性和财务口径的要求最高。它不适合替代腾讯的实时快照和分钟线。

目标数据分层：

| 能力 | 主源 | 备用 | 说明 |
|---|---|---|---|
| 实时行情 `quote` | 腾讯 | 新浪 | Tushare 实时权限单独收费，不作为默认方案 |
| 分钟线 `minute` | 腾讯 | 东财 | Tushare 分钟权限需单独购买 |
| 日/周/月 K 线 | **Tushare** | 本地快照 → 免费源（仅 research 模式） | 使用 `adj_factor` 统一复权 |
| 股票列表 | **Tushare** | akshare / baostock | 包含上市状态，需区分在市/退市 |
| 财务摘要/三表 | **Tushare** | 本地快照 → akshare（仅 research） | 必须保留公告日，避免未来函数 |
| 分红送转 | **Tushare** | 东财 | 以除权除息日为准 |
| 交易日历 | **Tushare** | 上证指数推导 | `trade_cal` 是官方交易日历入口 |
| 宏观 | **Tushare** | 东财镜像 / akshare | 先确认具体指标覆盖与口径 |
| 盘中交易信号 | 不适用 | 券商/付费行情 | 不把 Tushare 当日线当天用 |

---

## 二、为什么作为备选路径

### 优势

1. **契约稳定**：`ts_code`、`trade_date`、`open/high/low/close` 等字段长期稳定，比网页爬虫更适合做底层依赖。
2. **复权因子显式提供**：可以通过 `adj_factor` 自行计算前复权/后复权，不依赖上游临时口径。
3. **财务字段规范**：三表、财务指标、每日指标、分红等字段适合构建因子库。
4. **交易日历可靠**：比“用上证指数日线反推”更适合作为交易日权威来源。
5. **可增量更新**：按交易日拉全市场，适合落 Parquet/DuckDB。

### 风险与限制

1. **不是交易所官方数据，公开权限页也没有 SLA/赔付承诺。** 2025 年 8 月曾发生约一周的服务中断，不能把付费等同于高可用。
2. **积分与独立权限是长期成本。** 分钟、实时、新闻、公告等不包含在普通积分内。
3. **财务数据会修订。** 默认查询通常拿到最新修订值；回测必须做 Point-in-Time。
4. **接口权限和价格会调整。** 购买前以官方权限中心为准。
5. **存在再分发限制。** 不把下载的数据提交到公开仓库或对外提供数据服务，具体以 Tushare 授权条款为准。

## 三、计划中的实现形态

### 3.1 新适配器

计划新增一个可选适配器，不改变现有免费源：

```python
class TushareSource(BaseSource):
    name = "tushare"
    capabilities = (
        "kline", "list", "financial", "dividend", "calendar", "macro"
    )
```

**不实现** `quote` 和 `minute`，除非未来明确购买对应权限并单独设计实时链路。

### 3.2 依赖与配置

- 可选依赖：`tushare>=1.4`，放入 `pyproject.toml` 的 `[project.optional-dependencies].tushare`
- Token 只从环境变量读取：

```bash
export TUSHARE_TOKEN="..."       # Linux/macOS
setx TUSHARE_TOKEN "..."         # Windows，设置后重开终端
```

- 代码中只保留占位符，禁止把真实 Token 写入源码、Markdown、测试或 CI 日志。
- 未设置 Token 时：不注册 `tushare` 源，或抛出明确配置错误；**不能静默当作网络失败反复重试**。
- GitHub Actions 的真实接口测试使用仓库 Secret `TUSHARE_TOKEN`，默认 CI 不依赖它。

### 3.3 计划中的对外参数

以下 API 只是设计草案，当前版本不存在：

```python
fin = CNFin(
    tushare_token=os.getenv("TUSHARE_TOKEN"),
    quality="strict",       # strict / research
)
```

`quality` 语义：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| `strict` | 只允许 Tushare 或本地快照；失败明确报错 | 生产、正式回测 |
| `research` | 允许降级到免费源，但必须在 attrs 中暴露来源 | 探索、临时分析 |

**禁止**在生产模式下把 Tushare 失败静默切换成复权口径不同的免费源。

### 3.4 路由计划

```text
kline:      tushare → local snapshot → (research) eastmoney/baostock/tencent
financial:  tushare → local snapshot → (research) akshare
calendar:   tushare → local snapshot → 上证指数推导
quote:      tencent → sina
minute:     tencent → eastmoney
```

`prefer="tushare"` 在 `strict` 模式下必须意味着“只用 Tushare 或本地快照”，不能继续沿免费链降级。

## 四、数据标准化契约

### 4.1 代码与市场

- Tushare 使用 `600000.SH`、`000001.SZ`、`920001.BJ` 形式。
- 现有 `Symbol` 已能解析这些后缀；适配器负责 `code ↔ ts_code` 双向转换。
- 指数、ETF、可转债的代码后缀需要单独验证，不能只按 6 位数字推断。

### 4.2 日线单位

Tushare `daily` 的原始单位：

- `vol`：手
- `amount`：千元
- `pct_chg`：百分比

`cnfin.py` 的统一契约：

- `volume`：股（`vol × 100`）
- `amount`：元（`amount × 1000`）
- `pct_chg`：百分比，不再乘 100

### 4.3 复权

`daily` 是不复权行情。计划使用 `adj_factor` 统一计算：

```text
hfq_price = raw_price × adj_factor
qfq_price = raw_price × adj_factor / latest_adj_factor
```

注意：

- 回测取历史某日的前复权价时，应使用该日已知的复权因子，不能用未来最新因子回填。
- `volume` 不随价格复权；不要同时乘复权因子，否则量价关系被破坏。
- 前复权价格会随之后的分红变化，落库时应同时保存原始价与 `adj_factor`，不要只存复权价。

### 4.4 财务 PIT

财务数据必须保留：

- `ts_code`
- `end_date`：报告期
- `ann_date`：公告日
- `f_ann_date`：实际公告日
- `update_flag`：修订标记
- 报表类型/合并口径

回测取数规则：

```text
只用 ann_date <= 回测日 的最新可见版本
```

同一报告期出现修订时，不能直接用最新数据覆盖历史时点。建议落库为“报告期 + 公告日 + 版本”的不可变快照。

## 五、故障与限频语义

计划新增/明确以下异常路径：

| 情况 | 处理 |
|---|---|
| 未配置 Token | 配置错误，直接提示设置 `TUSHARE_TOKEN` |
| 积分不足/无接口权限 | 配置/授权错误，不进入无限降级重试 |
| 每分钟限频 | 指数退避重试，不计入“源永久死亡” |
| 服务端 5xx/网络故障 | 有界重试，失败后 strict 模式直接报错 |
| 数据为空 | `NoDataError`，不计入熔断 |
| 字段缺失/口径变化 | `SourceError`，记录 schema 差异 |

限频和权限错误的日志必须可区分，否则无法判断是“买错权限”还是“网络挂了”。

## 六、成本基线（2026-10-24 官方口径）

| 项目 | 个人价格 | 说明 |
|---|---:|---|
| 120 积分 | 免费 | 仅非复权日线，不适合严肃量化 |
| 2000+ 积分 | 200 元/年 | 日线、复权、周月线、财务等核心能力的试用起点 |
| 5000+ 积分 | 500 元/年 | 500 次/分钟，适合全市场批量更新 |
| 10000+ 积分 | 1000 元/年 | 增加部分特色数据权限 |
| 15000+ 积分 | 1500 元/年 | 更高特色数据权限 |
| A 股历史分钟 | 2000 元/年 | 独立权限，不含在积分内 |
| A 股实时分钟 | 1000 元/月 | 仅日内策略需要 |
| 实时日线 | 200 元/月 | A 股/指数/ETF 分项 |
| 机构价格 | 个人 10 倍 | 以官方权限中心为准 |

**建议**：先用 2000 积分档（200 元/年）验证 50–100 只股票、5 年数据；确认权限、字段和调用量后，再决定是否升 5000 档。分钟权限只在确有日内策略时购买。

官方依据：

- [积分与频次权限表](https://tushare.pro/document/2?doc_id=290)
- [接口最低积分说明](https://www.tushare.pro/document/1?doc_id=108)
- [A 股日线接口](https://tushare.pro/document/2?doc_id=27)

价格和权限可能调整，购买前务必以官方页面为准。

## 七、落地阶段与验收

### 阶段 1：适配器与离线测试

- 新增 `TushareSource`，通过 mock `pro_api` 返回构造数据。
- 覆盖：代码映射、单位转换、复权公式、报告期/公告日、空数据、权限错误、限频。
- 默认测试不访问真实 Tushare，不需要 Token。

**完成标准**：离线测试全绿；现有免费链路行为不变；未安装 `tushare` 时正常跳过。

### 阶段 2：小样本真实对账

- 选 50–100 只股票，覆盖沪深北、ETF、指数。
- 对比 5 年交易日、复权收盘、成交量、财务报告期。
- 差异必须逐项解释来源，不能只看“能不能返回数据”。

**完成标准**：交易日无无故缺口；复权差异可解释；财务报告期与公告日正确；限频行为符合预期。

### 阶段 3：本地快照

- 使用 Parquet 或 DuckDB 落库。
- 保存原始价、`adj_factor`、公告日版本和更新水位。
- 支持增量更新与断点续跑。

**完成标准**：Tushare 短时不可用时，策略可读取最近快照继续回放；不静默混用免费源。

### 阶段 4：生产切换

- `strict` 模式作为生产默认。
- 监控：请求成功率、限频次数、数据缺口、最新交易日延迟。
- 保留免费源作为人工核验工具，而不是自动替换主源。

## 九、明确不做的事

- 不把 Tushare 当作实时/Level-2 数据源。
- 不在未购买分钟权限时偷偷把日线当分钟线。
- 不把 Tushare 的复权价直接覆盖现有原始价缓存。
- 不把下载的数据提交到公开 GitHub 仓库。
- 不在默认 CI 中依赖付费接口或真实 Token。
- 不在 `strict` 模式下自动降级到复权/财务口径不同的免费源。
